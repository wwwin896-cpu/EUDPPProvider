## 二、本轮修复的 3 项

### 1. OfferCatalog 内 441 个 Service 节点缺 provider（结构化数据完整性）

每页 `OfferCatalog` 里有 3 个 `itemOffered` Service（EV / LMT / BESS），只有 `name`，没有 `provider` 实体引用。147 页 × 3 = **441 个节点**，占全站 588 个 Service 的 75%。

判定依据：Google 对 Service 的推荐属性包含 `provider`，缺失时实体图谱断链，AI 引擎无法把"这项服务"归到具体提供方。父级 Service 虽有 provider，但子节点不会自动继承。

修复：`src/layouts/Layout.astro` 三个 `itemOffered` 各补 `"provider": { "@id": "https://eudppprovider.com/#organization" }`。

复测：`Service_missing 441 → 0`。

### 2. AI 语料里的占位 URL 会被真实抓取（GEO 脏数据）

`llms.txt` 与 `llms-full.txt` 原文写 `https://eudppprovider.com/{locale}/{same-slug}/` 作为多语言路径规则。这是一个**看起来可抓取、实际必然 404** 的地址——AI 爬虫按字面请求会拿到 404，等于主动给引用源喂坏数据。

修复：改为纯路径写法 `/{locale}/{slug}/`，去掉域名前缀，保留同一行内的真实示例链接。

复测：语料内 URL 检查 `not_found 2 → 0`。

### 3. 残留绝对化措辞 2 处

| 位置 | 原文 | 改为 | 理由 |
|---|---|---|---|
| llms.txt 商业模式段 | `99.9% uptime SLA guarantee` | `99.9% uptime SLA` | "SLA"与"guarantee"并存属自相矛盾，SLA 是合同条款不是担保 |
| `/insights/sovereign-data-vault-zkp-privacy-guide/` | `10-year immutable audit guarantees` | `10-year immutable audit records` | 该句同时进入可见正文与 Answer schema，"guarantee"对未来十年的事实性承诺不可兑现 |

复测：全站 `guarantee` 出现次数 **5 → 3**。剩余 3 处经逐条判定保留：`/terms/` 服务抵扣条款（合同用语）、`/` 模块可维修性描述中的 "software support guarantee"、`/solutions/managed-data-hosting/` 的 "Core Guarantees" 区块标题。

## 五、一次过程事故（已修复，如实记录）

生成"`99.9% uptime SLA guarantee` → `99.9% uptime SLA`"替换时，我用了一条 PowerShell 内联 Python，写法是 `open(f,'w').write(open(f).read())`。由于 `open(f,'w')` 先执行并截断文件，随后读到的是空内容，**两份 llms 文件被写成 0 字节**。

发现路径：替换后立即跑的语料校验显示 `llms.txt len=0 / urls=0`，异常立刻暴露。

处置：`git checkout -- public/llms.txt public/llms-full.txt` 从 HEAD 恢复（改前已全部提交），改用"先读全文再写"的两步脚本重做替换，重建后复核语料 34 + 33 条 URL、0 条失效。

教训（已按团队红线记录）：不要把带写入的表达式写成单行内联，尤其目标与来源是同一文件。
